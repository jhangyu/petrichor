## 1. 天氣主頁 `WeatherScreen` **[已實作]**

**目的**：顯示使用者所在地的目前天氣、短期預報、一週預報；入口到雷達。
**進入**：App 啟動。**離開**：右上地圖圖示 → §2 雷達頁。
**資料流**：`weatherNotifierProvider`（weather_provider.dart:41-63）→ 定位 → `repo.get24hForecast(city, district)` → `getWeeklyForecast(city)` → 資料集 **F-D0047-089**（app_constants.dart:31）→ `WeeklyForecast.days` 取前 3 天映射成 `WeatherCondition{wx, pop(%), t(°C 整數=日最高溫), startTime(YYYY-MM-DD), endTime}`（weather_repository.dart:225-245, weather_models.dart:237-248）。

### 1.1 狀態

| 狀態 | 現況 UI | 行號 |
|---|---|---|
| Loading | 白色轉圈 + 「載入天氣資料...」 | weather_screen.dart:348-362 |
| Error | 紅色錯誤圖示 +「載入失敗」+ `Error: {原始例外字串}` + 「重試」按鈕（**onPressed 空實作**） | :364-403 |
| Empty | 雲斜線圖示 +「暫無天氣資料」+「請稍後再試，或檢查網路連線」（無動作） | :405-432 |
| Permission denied | **無 UI**，靜默退回臺北信義區，使用者不知道顯示的不是自己位置 | location_service.dart:36-49 |
| 下拉重新整理 | RefreshIndicator 存在但 `onRefresh` 空實作 | :81-84 |
| Stale / 離線快取 | 無 | — |

> 注意：`WeatherNotifier._init` 的例外被吞，但 `get24hForecast` 失敗回 `[]`（weather_repository.dart:243），所以 API Key 缺失/網路失敗實際走 **Empty** 而非 Error。設計需把「失敗」與「空」都做好。

### 1.2 區塊（由上至下）

**A. 位置標題列**（:104-140）
- 地名：`{city} {district}`，例「臺北市 信義區」
- 副標「當前天氣預報」（固定字串，無資訊量）
- 右側地圖圖示按鈕 → 雷達頁
- 缺：更新時間、切換地點、搜尋、設定入口

**B. 目前天氣卡**（:143-193）
- 大字溫度 `{t}°C`，例 `28°C`（來源實為「第一天最高溫」，非即時觀測）
- 天氣描述 `wx`，例「多雲時晴」
- 天氣圖示：**寫死太陽**（`Icons.wb_sunny` amber，:174），不隨天氣變
- 四個細項：體感 `{t}°`（= 溫度，假資料）｜降雨機率 `{pop}%`（真）｜風速 `--m/s`（寫死佔位）｜濕度 `--%`（寫死佔位）
- 資料模型 `CurrentWeather` 已有 `feelsLike/humidity/windSpeed/observationTime`（weather_models.dart:60-90）但 UI 未用；`getCurrentWeather` 用預報均溫與 PoP 冒充濕度（weather_repository.dart:150-161），也未被 provider 呼叫。

**C. 「未來24小時預報」橫向列**（:219-272）
- 每卡 120×160：時間（`startTime`，實為日期字串如 `2026-11-14`；`'now'`→「現在」）、雲圖示（寫死）、`{t}°C`、`降雨 {pop}%`
- 實際只有 ≤3 張卡（3 天資料），不是 24 小時。

**D. 「一週預報」直列**（:274-346）
- 每列：星期標籤、雲圖示（寫死）、低溫/高溫 `{t-2}° {t}°`（低溫是「高溫減 2」捏造）、`{pop}%` 膠囊
- 星期標籤陣列寫死 `['今天','明天','週二'…]`（:294），與實際日期無關
- 取樣 `i += 4`（:277）對 3 筆資料只會取到 1 列
- 資料模型 `DailyForecast` 本有真正 `minTemperature/maxTemperature/date/weatherCode`（weather_models.dart:186-229）未被使用

### 1.3 動畫
進場 fade/slide/scale（flutter_animate，各區塊 delay 300–900ms+），太陽圖示持續 shimmer 2s（:175-176）。

### 1.4 設計須涵蓋的完整功能（現有 + 資料已具備）
目前溫度、體感、濕度、風速、降雨機率、天氣現象（圖示隨 `WeatherPhenomenon`：晴/多雲/晴時多雲/陰/陣雨/雷陣雨/雨/毛毛雨/霧/未知，weather_models.dart:11-47）、今日高低溫、更新時間、逐 3 小時、7 日預報（日期/星期/天氣/高低溫/降雨）、定位狀態與手動選地點、重新整理、雷達入口。

## 4. Current UI problems（現況缺陷）

**資料真實性（最嚴重，設計不能照現況）**
1. 天氣圖示全部寫死：太陽 `weather_screen.dart:174`、雲 `:247`、`:308`；不隨天氣現象變化，與「雨」文字並列時自相矛盾。
2. 體感 = 溫度（:184）；風速、濕度為寫死 `--`（:186-187）——兩格永遠無資料。
3. 低溫為「高溫 − 2」捏造（:312）；真正的日高低溫（weather_models.dart:200-204）未用。
4. 「未來24小時預報」實為 ≤3 天日期卡，標題與內容不符（:225, weather_repository.dart:232-233）。
5. 一週預報 `i += 4` 取樣（:277）對 3 筆資料只剩 1 列；星期標籤寫死（:294）。

**狀態/回饋**
6. 重試按鈕、下拉重新整理皆空實作（:82-84, :389-391）。
7. 失敗與空資料混淆：預報失敗回 `[]`→顯示 Empty 而非 Error（weather_repository.dart:243）；Error 畫面直出 `Error: Exception…` 原始字串（:383）。
8. 雷達載入中/失敗完全無提示（radar_screen.dart:167-168）；無 Key 時使用者看到一張乾淨地圖。
9. 定位被拒靜默改臺北，無任何標示（location_service.dart:36-49）。
10. 無「最後更新時間」、雷達無觀測時間。

**版面/層級**
11. 位置標題副標「當前天氣預報」為無資訊文字（:114）；地名與目前溫度之間隔 40px 讓關鍵資訊分散（:90-92）。
12. 溫度 64px w200 極細字重，在玻璃卡上對比弱；中文字體未指定（app_theme.dart:9 Inter 無中文）。
13. 玻璃擬態 + 漸層：`GlassContainer` 白 20% 透明疊在深藍漸層，淺色環境（戶外看天氣的主要場景）可讀性差；每張卡都 BackdropFilter blur（glass_morphism.dart:41-44），列表中效能與視覺噪音皆高。
14. 區塊間距一律 40px（:90-97），無層級分組；三個預報區塊視覺權重相同，目前天氣與預報沒有主次。
15. 24h 卡 120px 寬 ×160 高內容稀疏（4 個元素佔大片空白）；一週列四欄用 spaceBetween，數字欄位不對齊（:300-342）。
16. 動畫過多：每區塊逐項延遲進場（delay 至 900ms+）+ 持續 shimmer 太陽（:175），首屏資訊要等動畫跑完。

**一致性**
17. 主題宣告 light/dark 但天氣頁背景寫死深色（:19-23），`scaffoldBackgroundColor: transparent`（app_theme.dart:11,23）；雷達頁底圖為淺色 OSM，卻用白色文字/玻璃面板，兩頁視覺語言斷裂。
18. 雷達 AppBar 白字疊淺色地圖（radar_screen.dart:37-40）；ChoiceChip 未選中黑字、選中白字，顏色混用 `Colors.blueAccent`（:134-135）。
19. 雷達源標籤與常數命名不一致（樹林 vs 新竹，app_constants.dart:50 vs radar_screen.dart:97）。
20. 無導覽結構：僅一個無標示圖示（純地圖 icon，無文字）通往雷達（:132），可發現性差；無法擴充 3.x 新頁。
21. 雷達疊圖邊界為示意值（:153-156）→回波與地理位置不對齊，屬功能錯誤而非純視覺。
